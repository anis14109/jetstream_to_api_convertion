This guide documents the files **created** and **modified** by the latest
hardening review on the Custom REST API (`/api/v1`). It focuses on the two
areas under review and does not change the public contract:

1. **Concurrency-safe cursors** - `last_pulled_cursor` and `acknowledged_cursor`
   are strictly monotonic; concurrent requests can never move a checkpoint
   backward.
2. **Email-change re-verification** - changing a verified email clears
   `email_verified_at`, sends a fresh verification mail to the new address and
   invalidates the previous verification link.

It builds on `1.0.6-concurrency-security-hardening-guide.md`.

Every file that was **created** or **modified** is listed with line-numbered
source (new files) or a unified diff (modified files).

## 1. Summary of changes

| Area | Files | What changed |
|------|-------|--------------|
| Cursor monotonicity | `app/Sync/SyncEngine.php` | `advanceCursor()` writes both checkpoints through one atomic `CASE WHEN col > N THEN col ELSE N END` UPDATE; `pull()` uses it for `last_pulled_cursor` and `ack()` locks the row with `lockForUpdate()` before advancing `acknowledged_cursor`. |
| ACK validation | `app/Sync/SyncEngine.php` | `ack()` rejects negative and ahead-of-delivery cursors and treats a duplicate/stale ACK as a no-op, so a checkpoint can never regress. |
| Email-change re-verification | `app/Services/Api/V1/ProfileService.php` | Changing the email clears `email_verified_at` inside the transaction, sends the verification notification after commit, and the signed link (keyed on the email) invalidates the old address. |
